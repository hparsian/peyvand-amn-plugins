# فاز ۸ — داشبورد امنیتی و انطباق

تاریخ: ۲۰ آبان ۱۴۰۵ (2026-11-11)
وضعیت: پیاده‌سازی‌شده — **تأیید نحوی انجام شد؛ اجرای زنده در وردپرس انجام نشده**

## ۱. دامنه

هشدارهای فاز ۰ تا ۷ جای‌های مختلفی بودند: نوتیس کلید در صفحه‌ی هسته، نوتیس
اعتبارنامه در پل پیامک، نسخه‌ی اسکیمای هر افزونه در آپشن خودش، تعارض‌های هویت
در بخش رجیستری. این فاز همه را در **یک بخش فقط‌خواندنی** جمع می‌کند.

## ۲. تغییرات — `pivand-amn-core` 1.5.1 → **1.6.0**

### `includes/class-compliance.php` (جدید)

`Pas_Core_Compliance::checks()` فهرستی از بررسی‌ها با ساختار
`key / title / status (ok|warn|fail|info) / detail` برمی‌گرداند:

| بررسی | منبع | وضعیت |
|---|---|---|
| کلید رمزنگاری اکوسیستم | `Pas_Core_Data_Audit::key_status()` | fail اگر تنظیم نشده باشد |
| اعتبارنامهٔ پل پیامک | `Pas_Melipayamak::uses_leaked_credentials()` (با `class_exists`) | fail اگر هنوز اعتبارنامهٔ لو‌رفته استفاده شود؛ info اگر پل فعال نباشد |
| اسکیمای هسته (رجیستری هویت) | `pas_core_db_version` vs `Pas_Core_Client_Registry::DB_VERSION` | warn در ناهم‌خوانی |
| اسکیمای نگاشت فیلد | `pas_mapper_db_version` vs `Pas_Core_Field_Mapper::DB_VERSION` | warn |
| اسکیمای پرونده | `pas_cf_db_version` vs `PAS_CF_VERSION` | warn |
| جدول‌های ثبت‌شده | `Pas_Core_Table_Registry::get_all()` + `SHOW TABLES LIKE` | warn با فهرست (حداکثر ۵) جدول غایب |
| تعارض‌های باز هویت | `COUNT(*)` روی جدول تعارض‌های خودِ هسته | warn اگر > ۰ |

- `summary()` شمارش سالم/نیازمند بررسی/مشکل را برای خلاصهٔ بالای صفحه می‌دهد.
- فیلتر `pas_compliance_checks` برای افزودن بررسی از افزونه‌های دیگر (ورودی
  اعتبارسنجی می‌شود؛ status نامعتبر به `info` تبدیل می‌شود).

### صفحهٔ پیشخوان

بخش «داشبورد امنیتی و انطباق» در صفحهٔ «زیرساخت پیوند امن»، پیش از بخش
وابستگی‌ها: یک خط خلاصه + جدول بررسی/وضعیت/توضیح.

## ۳. محدودیت‌های عمدی

- **فقط‌خواندنی**: هیچ اصلاح خودکار، هیچ دکمهٔ «درست کن».
- **هیچ کلید یا مقدار رمزنگاری‌شده چاپ نمی‌شود** — فقط «تنظیم شده/نشده» و
  منبع کلید.
- **مالکیت داده**: تعداد ردیف فقط برای جدول‌های خودِ هسته (تعارض‌های هویت)
  شمرده می‌شود؛ برای بقیه فقط وجود/نبود جدول بررسی می‌شود.
- **بدون تست رمزگشایی در این صفحه** — سنجش نمونه‌ای همان بخش «سنجش داده» است
  و عمداً دوباره اجرا نمی‌شود تا صفحهٔ پیشخوان سنگین نشود.

## ۴. تأییدها و محدودیت‌ها

انجام‌شده:

- پارسر PHP (`php-parser`، `suppressErrors: false`) روی فایل‌های تغییریافته.
- بازبینی: هیچ `insert/update/delete` در `class-compliance.php`.
- بازبینی: همهٔ فراخوانی‌های بین‌افزونه‌ای با `class_exists`/`method_exists` و
  `defined` محافظت شده‌اند (اگر پرونده یا پل پیامک فعال نباشد، بررسی حذف
  می‌شود، نه اینکه خطا بدهد).
- `unzip -t` روی بستهٔ ساخته‌شده.

انجام‌نشده (محدودیت محیط): PHP CLI، وردپرس و MySQL در دسترس نیستند، بنابراین
این‌ها **تست نشده‌اند**:

- اجرای واقعی `SHOW TABLES LIKE` و نمایش فهرست جدول‌های غایب.
- شمارش تعارض‌های باز و وضعیت warn آن.
- رفتار صفحه وقتی فقط هسته فعال است (پرونده/پل پیامک غیرفعال).
- نمایش با نقش‌های مختلف (این صفحه `manage_options` می‌خواهد).

## ۵. نقطهٔ بازگشت

- فقط یک فایل جدید + یک بخش نمایشی؛ هیچ تغییر اسکیما و هیچ داده‌ای نوشته
  نمی‌شود.
- بازگشت به 1.5.1 با حذف `require` و بخش نمایشی کار می‌کند.
