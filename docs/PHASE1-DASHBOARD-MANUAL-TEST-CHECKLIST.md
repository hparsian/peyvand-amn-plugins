# چک‌لیست تست دستی وردپرس — فاز ۱ داشبورد اکوسیستم (نسخه ۲.۷.۰)

دامنه: پرونده‌های بالینی (ثبت و ویرایش)، یادداشت جلسه، فرم ارزیابی مراجع، یادآور جلسه و مدیریت نوبت‌های پنل.

این سند برای اجرای دستی روی یک سایت **استیجینگ** نوشته شده است. هر بند یک شناسه دارد؛ نتیجهٔ هر بند را در جدول انتهای سند ثبت کنید. بخش I (امنیت) را حتماً با یک حساب غیرمدیر هم اجرا کنید.

## J. ممیزی و یکپارچگی داده

| # | گام | نتیجهٔ مورد انتظار |

| J1 | با `admin` → ماژول «ممیزی» | رکوردهای `case.save`، `case.intake`، `case.reminder`، `case.view`، `note.create`، `note.update`، `note.delete`، `note.restore`، `booking.create/status/update/delete/reminder` با نتیجهٔ `ok/error/denied` |
| J2 | متن یادداشت یا نام مراجع در ممیزی | ذخیره **نمی‌شود**؛ فقط نوع عمل، شناسه و نتیجه |
| J3 | ساختار جدول‌ها | هیچ جدول موازی برای پرونده/یادداشت/نوبت ساخته نشده؛ فقط جداول مالک (`pas_cf_*`، `zdp_bookings`) و دو جدول اختصاصی داشبورد (`pas_dashboard_audit`، `pas_dashboard_notifications`) |
| J4 | بعد از حذف یادداشت | ردیف یادداشت پاک/آرشیو شده اما نسخه‌های تاریخچه باقی است و بازگردانی کار می‌کند |
| J5 | رمزنگاری در دیتابیس | متن یادداشت و فیلدهای بالینی در جدول به‌صورت رمزشده است (خواندن مستقیم، متن روشن نشان نمی‌دهد) |
| J6 | لاگ سرور | هیچ `PHP Warning/Notice/Fatal` در `debug.log` ثبت نشده است |

نمونهٔ بررسی اختیاری با WP-CLI:

```bash
wp db query "SELECT id, full_name, phone, status, assigned_therapist FROM wp_pas_cf_cases ORDER BY id DESC LIMIT 10;"
wp db query "SELECT id, case_id, session_date, session_number FROM wp_pas_cf_notes ORDER BY id DESC LIMIT 5;"
wp db query "SELECT action, object_type, object_id, result, created_at FROM wp_pas_dashboard_audit ORDER BY id DESC LIMIT 20;"
```

> اگر پیشوند جدول‌های سایت غیر از `wp_` است (مثلاً `wp_2_`)، همان پیشوند را جایگزین کنید. نام جدول پرونده/یادداشت را با افزونهٔ پرونده هم‌خوان کنید.
