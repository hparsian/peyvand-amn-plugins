شاهد خام آزمون استیجینگ روی MariaDB واقعی — ۲۰۲۶-۱۱-۲۴
=========================================================

این فایل نتیجهٔ اجرای امروز روی یک سرور واقعی MariaDB (پروتکل MySQL، موتور
InnoDB) است، نه روی drop-in شبیه‌ساز SQLite. هیچ خط PASS/FAIL از اجرای قبلی
بازنویسی یا بازنویسی ادعاشده نشده است؛ لاگ کامل خام در
`staging-mysql-2026-11-24-raw.txt` (۴۳۷ خط) و CSV واقعی export در
`staging-mysql-2026-11-24-export.csv` کنار همین فایل است.

## چطور سرور بالا آمد

میزبان استیجینگ واقعی (سرور پروژه) همچنان در دسترس نبود و دسترسی root هم
ندارد (`sudo`: «no new privileges»؛ سوکت Docker: permission denied). بنابراین
خودِ سرور MariaDB به‌صورت unprivileged از بستهٔ رسمی باینری راه افتاد:

| مورد | مقدار |
|---|---|
| سرور | MariaDB 11.4.5-MariaDB، بیلد رسمی `linux-systemd x86_64` از archive.mariadb.org |
| راه‌اندازی | `mariadbd` با کاربر عادی، دیتادیر `/tmp/mysql/data`، سوکت `/tmp/mysql/mysql.sock`، `127.0.0.1:3307` |
| کتابخانهٔ جانبی | `libaio1t64` با `dpkg-deb -x` در پوشهٔ محلی (بدون نصب سیستم) و `LD_LIBRARY_PATH` |
| موتور ذخیره‌سازی | InnoDB (`@@default_storage_engine = InnoDB`) |
| دیتابیس | `wp_pas` — `utf8mb4` / `utf8mb4_unicode_ci` |
| sql_mode | `STRICT_TRANS_TABLES,ERROR_FOR_DIVISION_BY_ZERO,NO_AUTO_CREATE_USER,NO_ENGINE_SUBSTITUTION` |
| PHP | 8.3.32 (static-php-cli **bulk**: mysqli/mysqlnd/pdo_mysql، چون بیلد common فاقد mysqli است) |
| WordPress | 7.1.5 |
| WP-CLI | 2.12.0 |
| WP_DEBUG | روشن، `WP_DEBUG_LOG` روشن، `WP_DEBUG_DISPLAY` خاموش |

خروجی واقعی تأیید موتور:

```
version            comment          engine  ok
11.4.5-MariaDB     MariaDB Server   InnoDB  2d711642b726b04401627ca9fbac32f5c8530fb1903cc4db02258717921a4881
```

- `information_schema.TABLES` نشان می‌دهد هر ۱۲ جدول `wp_pas_*` روی InnoDB و با

- نام قراردادی ممیزی با نقطه روی MySQL هم سالم می‌ماند؛ ردیف واقعی جدول
  `wp_pas_dashboard_audit` پس از suite export:

```

```

- `migration`/`SHOW COLUMNS` و کوئری‌های اسکیمای داشبورد روی MySQL بدون خطا
  اجرا شدند و `wpdb last_error: none` در سناریوی سرتاسری ثبت شد.
- PHP این اجرا بیلد **bulk** است تا `mysqli` واقعی وجود داشته باشد؛ بیلد common
  فقط `pdo_mysql`/`mysqlnd` دارد و وردپرس با آن بالا نمی‌آید.

## اجرا نشد (نباید «قبول» شمرده شود)

- **میزبان استیجینگ واقعی پروژه** — این اجرا یک سرور MariaDB محلی و تازه بود،
  نه کلون سایت واقعی با داده و افزونه‌های همان میزبان.
- **Oracle MySQL 8.0** — فقط MariaDB 11.4.5 آزموده شد (نه 8.0 و نه 8.4).
- مرورگر، چیدمان RTL، جریان ۳۶۰px و بررسی بصری داشبورد.
- ارسال واقعی پیامک و ایمیل (فقط مسیر کد، صف و علامت‌گذاری بررسی شد).
- اسکریپت‌های HTTP فاز ۱۱ (`tests/phase11/*.php`) چون وب‌سرور محلی بالا نیامد؛
  `migration-verify` افزون بر آن به نصب نسخهٔ قدیمی داشبورد نیاز دارد.
- به‌روزرسانی واقعی از گیت‌هاب (نیازمند توکن و ترافیک به مخزن).

## برای اجرا روی میزبان استیجینگ واقعی چه چیزی لازم است

۱. دسترسی اجرای دستور روی همان میزبان (SSH یا کنسول پنل) با کاربری که
   `wp`/`php` را دارد، به‌همراه `WP-CLI` و `mysqli`.
۲. یک **کلون staging** از دیتابیس و `wp-content` که بازگردانی‌اش آزموده شده
   باشد، و `mysqldump` تازه پیش از شروع.
۳. اجازهٔ نصب ۱۲ بستهٔ `dist/` از پنل یا `wp plugin install` (روی میزبان‌هایی
   که `DISALLOW_FILE_MODS` دارند این کار از پیشخوان ممکن نیست).
۴. کلید رمزنگاری موجود روی همان سایت (`wp-config.php` یا
   `wp-content/pas-encryption-key.php`) — بدون چاپ کردن مقدارش.
۵. اگر ارسال واقعی پیامک/ایمیل هم لازم است: الگوی تأییدشدهٔ ملی‌پیامک و یک
   SMTP سالم روی همان staging.
۶. برای فاز ۱۱: یک وب‌سرور محلی روی همان میزبان که اسکریپت‌های HTTP را اجرا
   کند، و برای `migration-verify` یک نسخهٔ قدیمی داشبورد (۱.۹.۰) برای ارتقا.
