# چک‌لیست تست دستی وردپرس — فاز ۲ داشبورد اکوسیستم (نسخه ۲.۷.۰)

دامنه: دعوت به آزمون، مشاهدهٔ نتیجه و روند ارزیابی، گزارش آزمون، صندوق پیام مراجعان و پاسخ به آن، پیگیری لیدهای کوییز و مدیریت نظرسنجی/توصیه‌نامه.

این سند برای اجرای دستی روی یک سایت **استیجینگ** نوشته شده است. هر بند یک شناسه دارد؛ نتیجهٔ هر بند را در جدول انتهای سند ثبت کنید. تست‌های امنیتی (بخش F) را حتماً با یک حساب غیرمدیر هم اجرا کنید.

## B. ساخت دعوت‌نامه

در صفحهٔ «آزمون‌ها» → کارت «دعوت به آزمون».

| # | گام | نتیجهٔ مورد انتظار |
|---|---|---|
| B1 | فیلدها را بررسی کنید | «آزمون *»، «نام مراجع *»، «موبایل *»، «ایمیل (اختیاری)»، «اعتبار (روز، ۰ = بدون انقضا)» با مقدار پیش‌فرض مالک آزمون (معمولاً ۷)، و چک‌باکس تیک‌خوردهٔ «ارسال خودکار دعوت‌نامه به مراجع» |
| B2 | همه را خالی بگذارید و «ساخت دعوت‌نامه» را بزنید | مرورگر جلوی ارسال را می‌گیرد (فیلدهای اجباری HTML) |
| B3 | نام یک‌حرفی + موبایل معتبر بزنید | پیام خطای «نام مراجع را وارد کنید.» با رنگ خطا |
| B4 | نام درست + موبایل `12345` | پیام «شمارهٔ موبایل مراجع معتبر نیست.» |
| B5 | موبایل را با ارقام فارسی بنویسید (مثلاً `۰۹۱۲۳۴۵۶۷۸۹`) | پذیرفته می‌شود و در فهرست به شکل نرمال/ماسک‌شده ذخیره می‌شود |
| B6 | ایمیل نامعتبر مثل `a@b` وارد کنید | پیام «ایمیل واردشده معتبر نیست.» |
| B7 | اعتبار `۹۰` و سپس `-۵` و `۳۰۰` را امتحان کنید | مقدار بین ۰ تا ۹۰ محدود می‌شود (۳۰۰ → ۹۰) |
| B8 | چک‌باکس ارسال خودکار را **بردارید** و دعوت را بسازید | پیام موفقیت «دعوت‌نامه ساخته شد.»؛ هیچ پیامکی/ایمیلی ارسال نمی‌شود |
| B9 | بلافاصله بعد از ساخت، بالای صفحه را ببینید | کارت «لینک دعوت تازه» با نام مراجع و فیلد خواندنی لینک + دکمهٔ «کپی لینک» |
| B10 | دکمهٔ «کپی لینک» را بزنید | متن داخل فیلد در کلیپ‌بورد کپی می‌شود و متن دکمه دو ثانیه «کپی شد» می‌شود (بدون خطای کنسول) |
| B11 | صفحه را دوباره بارگذاری کنید (F5) | کارت «لینک دعوت تازه» **دیگر نیست** — لینک فقط یک‌بار نمایش داده می‌شود |
| B12 | با چک‌باکس ارسال خودکار و تنظیمات پیامک/ایمیل کامل، دعوت بسازید | یکی از سه پیام: «دعوت‌نامه ساخته و برای مراجع ارسال شد.» / «…ارسال امروز این مراجع قبلاً انجام شده و تکرار نشد…» / «…ارسال خودکار ناموفق بود؛ لینک دعوت را از کارت بالای صفحه بردارید.» |
| B13 | همان مراجع را دوباره و پشت‌سرهم دعوت کنید | در ارسال دوم باید پیام «throttle» دیده شود، نه ارسال تکراری |
| B14 | در فهرست، ستون «مراجع» را ببینید | نام پررنگ و موبایل ماسک‌شده با جهت `ltr` |

## D. نتیجه، روند و گزارش

پیش‌نیاز: یک دعوت را با لینک واقعی باز کنید، آزمون را کامل پاسخ دهید و ثبت کنید.

| # | گام | نتیجهٔ مورد انتظار |
|---|---|---|
| D1 | در فهرست، روی «نتیجه و روند» دعوت تکمیل‌شده بزنید | صفحهٔ نتیجه با دکمهٔ «بازگشت به فهرست دعوت‌نامه‌ها» |
| D2 | کارت «مراجع» | «نام»، «موبایل» ماسک‌شده با `ltr`، «وضعیت دعوت» = «تکمیل‌شده»، «نتیجهٔ ثبت‌شده» = تعداد نمرات |
| D3 | کارت «روند ارزیابی» | جدول با ستون‌های «آزمون»، «نمرهٔ کل»، «تغییر»، «تاریخ»، «گزارش»؛ ردیف‌ها از جدید به قدیم |
| D4 | ستون «تغییر» | ردیف اول `—`؛ ردیف‌های بعدی همان آزمون `▲ +` یا `▼` نسبت به نمرهٔ قبلی |
| D5 | برای مراجعی که فقط یک نتیجه دارد | هیچ مقدار `NaN` یا خالی غیرمنتظره دیده نمی‌شود |
| D6 | کارت «فهرست نتایج تکمیل‌شده» | فهرست نام آزمون‌های تکمیل‌شدهٔ همان شماره |
| D7 | دعوتی که هنوز پاسخ نداده را باز کنید و نتیجه را از نشانی صدا بزنید | «هنوز نتیجه‌ای برای این مراجع ثبت نشده است.» |
| D8 | روی «مشاهدهٔ گزارش» بزنید | عنوان «گزارش <نام آزمون> — <نام مراجع>»، دکمهٔ «بازگشت به نتیجه و روند» و HTML کامل گزارش مالک آزمون |
| D9 | در گزارش، نمودارها را ببینید و کنسول مرورگر را باز کنید | نمودارها رسم می‌شوند و خطای `Chart is not defined` یا ۴۰۴ اسکریپت وجود ندارد |
| D10 | گزارش را با آزمونی که نمودار میله‌ای/خطی دارد هم امتحان کنید | CSS و ظاهر گزارش با صفحهٔ گزارش خود افزونهٔ آزمون یکسان است |
| D11 | با `therapist` نشانی گزارش مراجعی خارج از پرونده‌هایش را باز کنید | «مشاهدهٔ این گزارش برای شما مجاز نیست.» |
| D12 | با `therapist` صفحهٔ نتیجهٔ مراجع خارج از دامنه | «این مراجع در پرونده‌های شما نیست؛ مشاهدهٔ نتیجه مجاز نیست.» |
| D13 | `attempt_id` نامعتبر (مثلاً حروف یا عدد بزرگ) در نشانی | «گزارشی برای این مراجع یافت نشد.» بدون خطای PHP |
| D14 | اگر `PAS_CORE_ENCRYPTION_KEY` را موقتاً بردارید (فقط استیجینگ) | گزارش با پیام «دادهٔ نتیجه قابل خواندن نیست (کلید رمزنگاری را بررسی کنید).» رد می‌شود، نه با صفحهٔ سفید |

## E. صندوق پیام مراجعان

پیش‌نیاز: از پنل مراجع (فرم تماس پنل) یک پیام با شمارهٔ یک مراجع ثبت کنید.

| # | گام | نتیجهٔ مورد انتظار |
|---|---|---|
| E1 | صفحهٔ «ارتباطات» را باز کنید | خلاصه به شکل «N پیام، M خوانده‌نشده.» |
| E2 | پیام تازه | کارت با کلاس تیره‌تر (خوانده‌نشده)، نشان «خوانده نشده» و موبایل ماسک‌شده |
| E3 | متن پیام چندخطی بفرستید | خطوط شکسته حفظ می‌شوند (`nl2br`) و HTML خام اجرا نمی‌شود |
| E4 | پاسخ خالی بفرستید | مرورگر جلوگیری می‌کند (فیلد اجباری) |
| E5 | پاسخ «تست پاسخ» را بنویسید و «ثبت پاسخ» بزنید | پیام «پاسخ برای مراجع ثبت شد.»، بازگشت به همان صفحه، وضعیت «پاسخ داده شده»، بخش «پاسخ فعلی: تست پاسخ» |
| E6 | همان پیام را دوباره باز کنید | متن پاسخ در textarea از پیش پر شده است |
| E7 | پاسخ را ویرایش کنید و دوباره ثبت کنید | پاسخ قبلی جایگزین می‌شود (ردیف جدید ساخته نمی‌شود) |
| E8 | از پنل مراجع پاسخ را ببینید | مراجع همان پاسخ را می‌بیند (مسیر قبلی پنل، بدون جدول موازی) |
| E9 | بیش از ۵۰ پیام ثبت کنید | فقط ۵۰ پیام آخر با پیام «فقط ۵۰ پیام آخر نمایش داده شده است.» |
| E10 | افزونهٔ پنل مراجعان را موقتاً غیرفعال کنید | «صندوق پیام در دسترس نیست (افزونهٔ پنل مراجعان فعال نیست یا نسخهٔ آن قرارداد پیام را ندارد).» و بقیهٔ صفحه سالم می‌ماند |
| E11 | با کاربری که فقط `PAS_DASHBOARD_CAP` دارد (بدون `pas_dashboard_send_messages`) فرم پاسخ را POST کنید | ۴۰۳ «دسترسی به این عملیات مجاز نیست.» و بدون تغییر در جدول پیام‌ها |
| E12 | `message_id` ناموجود (مثلاً `999999`) بفرستید | پیام «ثبت پاسخ ناموفق بود یا پیام یافت نشد.»، بدون Warning |
| E13 | با `therapist` پاسخ پیامی از مراجع خارج از پرونده‌هایش را ثبت کنید (هم از فرم، هم POST دستکاری‌شده به `message.reply`) | همان پیام در فهرست با «خارج از دامنهٔ شما — پاسخ فقط برای مراجعان پرونده‌های شما ثبت می‌شود.» و بدون فرم پاسخ؛ POST مستقیم هم «این پیام از مراجعان پرونده‌های شما نیست.» و جدول `wp_zdp_messages` بدون تغییر |
