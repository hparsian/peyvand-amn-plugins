## ۱. چه چیزی ساخته شد

صفحهٔ تازهٔ `pas-core-center` («مرکز مدیریت») به‌عنوان اولین زیرمنوی «زیرساخت
پیوند امن» اضافه شد؛ کاملاً **فقط‌خواندنی** است و هیچ تنظیمی را تغییر نمی‌دهد.

| فایل | تغییر |
| --- | --- |
| `pivand-amn-core/includes/class-center.php` | **جدید** — صفحه + جمع‌آوری داده |
| `pivand-amn-core/assets/css/center.css` | **جدید** — کارت‌ها، نمودارها، جدول‌ها، نشان‌ها، موبایل |
| `pivand-amn-core/assets/js/center.js` | **جدید** — ساخت نمودارها + fallback بدون JS |
| `pivand-amn-core/assets/vendor/apexcharts/` | **جدید** — ApexCharts 3.54.1 (MIT) + LICENSE |
| `pivand-amn-core/includes/class-admin.php` | زیرمنو + enqueue مخصوص همین صفحه |
| `pivand-amn-core/pivand-amn-core.php` | require + نسخه `1.8.0` |

## ۲. محتوای صفحه و منبع هر عدد

| بخش | منبع |
| --- | --- |
| افزونه‌های فعال (x از y) | `Pas_Core_Health::report()` |
| سلامت / انطباق (سالم، هشدار، مشکل) | `Health` + `Pas_Core_Compliance::checks()/summary()` |
| جدول‌های دیتابیس (موجود از اعلام‌شده) | `Health` (missing_tables) |
| کلید رمزنگاری | `Pas_Core_Data_Audit::key_status()` |
| پیامک (تنظیم‌شده/نشده + ارسال ۲۴ ساعت اخیر) | آپشن‌های `pas_sms_*` + جدول `{prefix}pas_sms_log` |
| ایمیل | آپشن `zsm_settings` (host/username یا کلید Brevo) |
| نمودار دونات | توزیع وضعیت سلامت همان گزارش |
| نمودار میله‌ای | جدول‌های موجود/غایب هر افزونه |
| آخرین تلاش‌های پیامک | ۵ ردیف آخر جدول لاگ — شماره **ماسک‌شده**، بدون متن پیام |

هیچ دادهٔ نمایشی یا مقدار ثابت در قالب وجود ندارد: اگر افزونه‌ای نصب نباشد یا
لاگ خالی باشد، پیام «نصب نشده / لاگ خالی» نمایش داده می‌شود، نه عدد ساختگی.

## ۳. ApexCharts سلف‌هاست

`apexcharts.min.js` (۵۲۷KB) و `LICENSE` (MIT) در `assets/vendor/apexcharts/`
قرار گرفتند و **فقط** با هوک همین صفحه enqueue می‌شوند — هیچ CDN، هیچ بارگذاری
سراسری. اگر فایل در دسترس نباشد، `center.js` به‌جای کرش کردن، پیام جایگزین
می‌گذارد و بقیهٔ صفحه کار می‌کند.

## ۶. باقی‌مانده‌ها

1. کارت «ایمیل (SMTP)» در Staging «تنظیم نشده» است — چون SMTP روی این نصب
   پیکربندی نشده؛ این وضعیت واقعی است، نه باگ.
2. لاگ پیامک Staging پر از ارسال‌های ناموفق آزمون («پارن یافت نشد یا تایید نشده»)
   است؛ همان داده‌های واقعی تست‌های قبلی است و پاک نشد.
3. نمودار روند زمانی (مثلاً جلسات/آزمون‌های ۱۴ روز اخیر) نیازمند یک فیلتر
   مشترک از افزونه‌های دیگر است؛ در این گام عمداً فقط داده‌ای که هسته خودش
   می‌تواند معتبر بسازد نمودار شد تا هیچ عدد تقریبی/ساختگی نمایش داده نشود.
4. گام ۶ (پاک‌سازی: حذف Google Fonts/jsdelivr، یکدست‌سازی فرم‌های sms/smtp/2fa/
   feed/contact و سناریوی ۱۷ گامی) باقی است.
