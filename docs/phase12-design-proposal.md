# فاز ۱۲ — طرح طراحی (Design Proposal)

تاریخ: ۲۰ آبان ۱۴۰۵ (2026-11-12) · پیوست ممیزی: [`phase12-ui-audit.md`](phase12-ui-audit.md)
وضعیت: **پیشنهاد — در انتظار تأیید برای شروع پیاده‌سازی**

---

## ۱. اصول طراحی

1. **آرام، گرم، حرفه‌ای** — پالت شنی/کرم/قهوه‌ای برای یک فضای درمانی؛ بدون رنگ‌های
   پرجنب‌وجوش، بدون گرادیان تزئینی.
2. **RTL-native** — همهٔ فاصله/حاشیه/تراز با CSS Logical Properties
   (`margin-inline-start`, `border-inline-end`, `padding-block`)، نه `left/right`.
   هیچ stylesheet جداگانه‌ای برای RTL لازم نیست.
3. **Mobile-first** — طرح از ۳۶۰px نوشته می‌شود و با `min-width` بزرگ می‌شود.
4. **دسترس‌پذیری از روز اول** — کنتراست AA، فوکوس مرئی، ناوبری کیبورد، `aria-live`
   برای پیام‌ها، احترام به `prefers-reduced-motion`.
5. **بدون آلودگی سراسری** — هیچ قاعده‌ای روی `html/body` جز در پوسته‌های اختصاصی
   (صفحهٔ ورود/پنل) و هیچ کتابخانه‌ای به‌صورت سراسری بارگذاری نمی‌شود.
6. **همه‌چیز از یک منبع** — رنگ/فاصله/شعاع/سایه فقط در توکن‌ها؛ هیچ رنگ هاردکد
   در کامپوننت‌ها.

## ۳. تایپوگرافی

- فونت: **Vazirmatn** سلف‌هاست (۴ وزن: 400/500/600/700، `woff2`, `font-display: swap`)
  + `Vazirmatn` از Google حذف می‌شود. تا زمانی که فایل‌ها اضافه نشده‌اند،
  fallback: `Tahoma, Arial, sans-serif`.
- مقیاس (rem، فاصلهٔ خط ۱.۷ برای فارسی):
  `--pui-fs-xs .75` · `sm .8125` · `base .9375` (۱۵px) · `md 1.0625` ·
  `lg 1.25` · `xl 1.5` · `2xl 1.875` · `3xl 2.25`
- وزن: متن 400، برچسب 500، تیتر کارت 600، تیتر صفحه 700.
- اعداد فارسی در نمایش تاریخ/شماره با `font-variant-numeric` و helper موجود
  (`Jalali`) — بدون تغییر منطق.

## ۴. فاصله، شعاع، سایه، حرکت

- فاصله: مقیاس ۴px (`--pui-s1..s8` = 4,8,12,16,20,24,32,40).
- شعاع: `sm 8` · `md 12` · `lg 16` · `xl 22` · `full 999`.
- سایه: دو سطح (کارت، شناور) با رنگ قهوه‌ای کم‌شفاف، نه سیاه خالص.
- حرکت: `160ms` و `220ms`، فقط `transform/opacity`؛ در
  `prefers-reduced-motion: reduce` همه صفر می‌شوند.

## ۵. آیکون‌ها

- یک اسپرایت SVG inline (`PUI::icon('calendar')`) با آیکون‌های 24×24،
  stroke 1.75، برگرفته از زبان بصری Tabler Icons؛ بدون CDN، بدون فونت آیکون.
- آیکون تزئینی `aria-hidden="true"` و آیکون معنادار با `role="img"` + `<title>`.
- ایموجی‌های منوی آزمون (`💑 📈 ⚙️ …`) حذف و با آیکون SVG جایگزین می‌شوند
  (متن منو تغییر نمی‌کند).

## ۶. کتابخانهٔ کامپوننت‌ها (از Tabler الگو گرفته، بدون Bootstrap)

Tabler به‌عنوان مرجع بررسی شد: توکن‌های CSS، حالت رنگ با `data-bs-theme` روی
`<html>`، آیکون‌های inline SVG، و اجزای کارت/جدول/تب/بج/مدال/تایم‌لاین.
**خود Bootstrap/Tabler بارگذاری نمی‌شود** (تداخل با Astra/Elementor و ~۳۰۰KB اضافه)؛
فقط الگوها و نام‌گذاری بازتولید می‌شوند. انتخاب حالت رنگ با `data-pui-theme`
روی `<html>` (`light|dark|auto`) و ذخیره در `localStorage` است.

| کامپوننت | کلاس | نکتهٔ دسترس‌پذیری |
|---|---|---|
| دکمه | `pui-btn` (+ `-primary/-ghost/-danger/-icon`) | فوکوس‌رینگ ۲px، حداقل ۴۴×۴۴ در موبایل |
| کارت | `pui-card` + `pui-card__head/__body/__foot` | تیتر با `aria-labelledby` |
| کارت آماری | `pui-stat` | مقدار با `aria-live="polite"` وقتی دینامیک است |
| بج/چیپ | `pui-badge` (+ وضعیت‌ها) | متن + آیکون، نه فقط رنگ |
| هشدار | `pui-alert` (`role="status"`/`alert`) | قابل بستن با Esc |
| فرم | `pui-field`, `pui-input`, `pui-select`, `pui-check` | `<label for>` اجباری، پیام خطا با `aria-describedby` |
| جدول | `pui-table` (+ `--sticky`, `--cards` در موبایل) | `<caption>`/`scope`, تبدیل به کارت زیر ۷۶۸px |
| تب | `pui-tabs` (`role=tablist/tab/tabpanel`) | فلش‌ها + Home/End |
| مرحله‌بندی | `pui-steps` | `aria-current="step"` |
| تایم‌لاین | `pui-timeline` | لیست معنادار `<ol>` |
| مدال | `pui-modal` (native `<dialog>`) | focus trap خودکار، Esc |
| توست | `pui-toast` | `aria-live="assertive"` |
| خالی‌بودن | `pui-empty` | آیکون + پیام + اقدام |
| اسکلتون | `pui-skeleton` | `aria-busy="true"` روی ناحیه |
| نوار پیشرفت | `pui-progress` | `role="progressbar"` + `aria-valuenow` |
| آواتار | `pui-avatar` | حرف اول، `aria-label` نام |
| ناوبری | `pui-nav` (سایدبار دسکتاپ / تب پایین موبایل) | skip-link، `aria-current="page"` |

PHP helperها: `pui_card_open()/close()`, `pui_alert()`, `pui_badge()`,
`pui_stat()`, `pui_empty()`, `pui_table_open()/close()`, `pui_field()`,
`pui_steps()`, `pui_icon()` — همه با `esc_*` داخلی و قابل استفاده در هر افزونه.

## ۷. چهار محیط — طرح

### ۷.۱ صفحهٔ ورود مراجع (`/panel/`, وقتی لاگین نیست)

```
┌──────────────────────────── نیمهٔ برند (دسکتاپ) ────────────────────────────┐
│  نشان «پیوند» + نام «پیوند امن»        │  کارت ورود (حداکثر ۴۲۰px)          │
│  یک جملهٔ آرام دربارهٔ محرمانگی         │  گام ۱: موبایل / ایمیل             │
│  سه نشان اعتماد (رمزنگاری، محرمانگی،    │  گام ۲: کد ۵ رقمی + شمارش معکوس     │
│  پاسخ انسانی) با آیکون                  │  پیام وضعیت + «تغییر شماره»         │
└─────────────────────────────────────────┴──────────────────────────────────┘
```
- موبایل: تک‌ستونی؛ برند در بالا فشرده.
- مرحله‌بندی واقعی با `pui-steps` (گام ۱/۲) و انیمیشن نرم؛ IDهای موجود
  (`#zdp-mobile`, `#zdp-otp`, `#zdp-otp-timer`, `#zdp-login-message`, …) حفظ می‌شوند.
- شمارش معکوس با `aria-live="off"` (تا هر ثانیه اعلام نشود) و متن دکمهٔ ارسال مجدد.
- خطا: پیام کوتاه زیر فیلد + `role="alert"`؛ خطای شبکه با دکمهٔ «تلاش دوباره».
- هیچ تغییر در منطق OTP/نرخ‌محدودیت.

### ۷.۲ پنل مراجع

- پوسته: سایدبار ۲۴۰px در ≥۱۰۲۴px، تب پایین ۵ آیتمی در موبایل، هدر با آواتار،
  نام، شماره، دکمهٔ خروج.
- داشبورد: ۴ کارت آماری (نوبت بعدی، آزمون‌های در انتظار، پیام‌ها، وضعیت پرونده)
  + نوار «اقدام لازم» (فرم ارزیابی ناتمام) + آخرین جلسات.
- تب‌ها: نوبت‌ها (لیست/رزرو)، آزمون‌ها، پیام‌ها، فرم ارزیابی، نظرسنجی، **تنظیمات
  حساب** (جدید، فقط نمایش/ویرایش ایمیل و اعلان‌ها با همان API موجود؛ اگر API نبود،
  فقط نمایش).
- اطلاعات بالینی: هیچ متن یادداشت درمانگر در پنل مراجع نمایش داده نمی‌شود؛
  نتایج آزمون فقط از مسیر توکن‌دار موجود. طراحی هیچ endpoint جدیدی باز نمی‌کند.

### ۷.۳ پنل درمانگر

یک منوی واحد «پیوند امن» در پیشخوان با زیرمنوهای موجود (پرونده‌ها، آزمون‌ها،
مدیریت) و **داشبورد جلسات** به‌عنوان صفحهٔ اول:
- نوار بالای صفحه: تاریخ امروز (جلالی)، تعداد جلسات امروز، مراجعان فعال، آزمون‌های
  در انتظار، هشدارهای سیستم.
- تقویم هفتگی (بدون کتابخانهٔ سنگین؛ گرید CSS + دادهٔ موجود نوبت‌ها).
- جدول «جلسات امروز» با وضعیت، ساعت، مراجع، اقدام (بازکردن پرونده).
- کارت «مراجعان اخیر» و «یادآورها».
- همهٔ لینک‌ها به صفحات فعلی با همان کپابیلیتی (`PAS_CF_CAP`);
  هیچ صفحهٔ جدیدی بدون بررسی دسترسی ساخته نمی‌شود.

### ۷.۴ مرکز مدیریت و مانیتورینگ

صفحهٔ `pas-core-center` (زیرمجموعهٔ هسته) با چهار بلوک — همه از دادهٔ واقعی:
1. **سلامت افزونه‌ها**: جدول ۱۰ افزونه (نسخه، فعال، جدول‌های غایب، وضعیت) از
   `Pas_Core_Health::report()` + بج وضعیت.
2. **قراردادها و وابستگی‌ها**: از رجیستری‌های `class-client-registry.php`.
3. **سرویس‌ها**: وضعیت پیامک (تنظیم‌شده/آخرین ارسال/نرخ موفقیت ۳۰ روز از
   `pas_sms_log`) و ایمیل (SMTP configured + آخرین خطا از جدول لاگ SMTP).
4. **نمودارها** (ApexCharts، فقط در همین صفحه، lazy): روند جلسات ۱۴ روز، خطاهای
   سیستم ۱۴ روز (از `pas_cf_audit_log`/لاگ‌ها)، وضعیت آزمون‌ها (donut)، عملکرد پیامک
   (موفق/ناموفق)، سلامت اجزا (bar).
هر عدد باید از کوئری واقعی بیاید؛ اگر داده نبود، `pui-empty` با «داده‌ای ثبت نشده»
نمایش داده می‌شود — هرگز دادهٔ نمایشی به‌عنوان وضعیت واقعی.

## ۸. حالت تاریک

- انتخاب با `data-pui-theme="light|dark|auto"` روی `<html>`، ذخیره در
  `localStorage`؛ پیش‌فرض **light** (چون امروز پنل عمداً روشن است و مراجعان
  انتظار همان را دارند)، `auto` قابل انتخاب.
- تغییر بدون رفرش، فقط با عوض‌شدن متغیرها؛ هیچ رنگ هاردکدی در دارک بازنویسی نمی‌شود.
- کنتراست دارک هم اندازه‌گیری شده (جدول بخش ۲).
- در صفحهٔ ورود/پنل، کل صفحه مالِ ماست؛ در پیشخوان فقط نواحی `.pui-shell`
  تحت تأثیر قرار می‌گیرند تا ظاهر پیشخوان وردپرس دست‌نخورده بماند.

---

## ۹. دسترس‌پذیری (چک‌لیست اجرایی)

- کنتراست AA برای همهٔ جفت‌های متن/پس‌زمینه (جدول بخش ۲).
- `:focus-visible` سراسری در محدودهٔ `pui` با outline 2px و offset 2px.
- skip-link در پوسته‌های تمام‌صفحه.
- همهٔ فیلدها `<label>` واقعی؛ خطاها `aria-describedby` + `role="alert"`.
- تب‌ها/مراحل با کیبورد (Arrow/Home/End) و `aria-selected`/`aria-current`.
- تصاویر/آیکون‌ها: `alt` یا `aria-hidden`.
- احترام به `prefers-reduced-motion` و `prefers-contrast: more`.
- هدف لمسی ≥۴۴px؛ فاصلهٔ حداقلی ۸px بین اهداف.
- تست خودکار: Playwright + `@axe-core/playwright` روی ۴ محیط × light/dark ×
  موبایل/دسکتاپ.

## ۱۰. عملکرد و بارگذاری

| مورد | تصمیم |
|---|---|
| CSS | ۳ فایل کوچک (`tokens`, `components`, `shell`) — فقط در صفحات نیازمند |
| JS | `ui.js` (≈۶KB) فقط در پوسته‌های pui؛ `charts.js` فقط در مرکز مدیریت |
| ApexCharts | سلف‌هاست در `assets/vendor/apexcharts/`، بارگذاری با `IntersectionObserver` هنگام دیده‌شدن بلوک نمودار |
| SortableJS | از jsdelivr حذف و سلف‌هاست (فقط صفحهٔ تنظیمات آزمون) |
| Google Fonts | حذف از `piwand-daily-feed` و `payvand-contact`؛ فونت مشترک |
| jQuery | برای کد جدید لازم نیست؛ فقط جایی که کد موجود وابسته است می‌ماند |
| کش | نسخه‌گذاری با `filemtime()` در حالت `WP_DEBUG`، وگرنه نسخهٔ افزونه |
| تکرار | `wp_style_is(...,'enqueued')` گارد؛ ثبت با `wp_register_*` یک‌بار |

بودجه: افزودن < ۳۵KB CSS و < ۱۲KB JS به صفحات بازطراحی‌شده (بدون نمودار).

├── assets/
│   ├── css/tokens.css              # پالت، تایپ، فاصله، شعاع، سایه، دارک

قراردادهای عمومی (بعد از انتشار قابل تغییر نیستند):

```php
PUI::enqueue( 'auth' | 'panel' | 'admin' | 'center' );  // شرطی و idempotent
PUI::handle( 'components' ): string;                     // برای dependency
PUI::icon( string $name, array $args = [] ): string;      // SVG امن
PUI::theme_attr(): string;                                // data-pui-theme
pui_card_open( array $args ), pui_card_close(), pui_alert( $type, $text, $args ),
pui_badge( $label, $tone ), pui_stat( $label, $value, $meta ),
pui_empty( $title, $text, $action ), pui_field( $args ),
pui_table_open( $cols ), pui_table_close(), pui_steps( $steps, $current )
```

- **بدون وابستگی اجباری:** اگر UI Kit فعال نباشد، افزونه‌ها به CSS فعلی خودشان
  fallback می‌کنند (`class_exists('PUI')` + `pui_*` guards). یعنی غیرفعال‌کردن UI Kit
  هیچ صفحه‌ای را سفید نمی‌کند.
- **بدون تغییر داده:** هیچ جدول/گزینه‌ای اضافه نمی‌شود جز یک گزینهٔ سبک
  (`pui_settings` برای رنگ پیش‌فرض/فونت) — اختیاری و additive.
