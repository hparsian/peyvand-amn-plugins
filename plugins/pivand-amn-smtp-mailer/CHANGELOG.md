# Changelog

## 1.5.6 — قرارداد داشبورد یکپارچه: وضعیت، تست و صف
- `ZSM_Smtp_Mailer::dashboard_status()`: روش ارسال، فرستنده و آمادگی تنظیمات را بدون برگرداندن رمز/API Key برمی‌گرداند.
- `ZSM_Smtp_Mailer::dashboard_send_test($to)`: تست ارسال از داشبورد با همان مسیر `wp_mail` و خطای `WP_Error` (بدون nonce/ریدایرکت صفحهٔ ادمین؛ مجوز در Action Bus داشبورد بررسی می‌شود).
- `ZSM_Mail_Queue::dashboard_summary()`، `::dashboard_queue()` و `::dashboard_retry()`: خواندن صف برای داشبورد بدون ستون `payload` (متن کامل ایمیل) و تلاش دوبارهٔ دستی با نتیجهٔ ساختاریافته.
- فیلتر `zsm_dashboard_queue` برای مصرف‌کننده‌های دیگر؛ بدون تغییر اسکیمای دیتابیس یا منطق ارسال خودکار/retry cron.
- `ZSM_VERSION` از 1.5.5 به 1.5.6.

## 1.5.5 — نمایش تاریخ شمسی در صف/لاگ ایمیل
- ستون «تاریخ» جدول صف/لاگ ایمیل با `pas_jalali_datetime()` شمسی نمایش داده می‌شود (در نبود هستهٔ مشترک، همان مقدار میلادی). ذخیره‌سازی در دیتابیس میلادی/UTC می‌ماند تا مرتب‌سازی و پاک‌سازی ۳۰ روزه بی‌تغییر کار کند.
- `ZSM_VERSION` از 1.5.4 به 1.5.5. بدون تغییر اسکیمای دیتابیس یا منطق ارسال/retry.

## 1.5.4 — فاز ۱۲ / گام ۶: پالت برند + فونت سلف‌هاست
- `assets/css/admin.css`: توکن‌های `--pivand-*` در محدودهٔ `.zsm-admin` به پالت پیوند امن نگاشت شدند و ورودی‌ها/دکمه‌های فرم یکدست شدند (دکمهٔ اصلی قهوه‌ای/کرم، فوکوس با رنگ برند).
- فونت Vazirmatn سلف‌هاست (کیت، سپس هسته) به‌عنوان dependency استایل — بدون هیچ درخواست به Google Fonts.
- رفع خطای نام‌فضا: در فایل‌های namespace‌دار `PUI`/`Pas_Core_Fonts` با `\` کامل صدا زده می‌شوند (وگرنه `Pivand\SmtpMailer\PUI` جست‌وجو می‌شد و صفحه با Fatal Error می‌افتاد).
- `ZSM_VERSION` از 1.5.3 به 1.5.4.

## 1.5.3 — پاکسازی دوره‌ای جدول صف/لاگ ایمیل
- رفع باگ (بازبینی عمیق): جدول `zsm_mail_queue` هم صف retry است و هم لاگ ارسال، و **هیچ پاکسازی‌ای نداشت**. هر ایمیل موفق یا شکست‌خورده یک ردیف با `payload` کامل (متن/HTML ایمیل) می‌نوشت؛ یعنی رشد بی‌پایان دیتابیس و نگه‌داری بی‌مدت متن ایمیل‌ها (احتمال داده‌ی شخصی).
- حالا حداکثر یک‌بار در روز، ردیف‌های پایان‌یافته (`sent`/`given_up`) قدیمی‌تر از ۳۰ روز حذف می‌شوند. ردیف‌های `pending` هرگز به‌خاطر سن حذف نمی‌شوند تا ایمیلی که در انتظار retry است گم نشود.
- پاکسازی داخل همان کران ۵ دقیقه‌ای (`zsm_process_mail_queue`) اجرا می‌شود و با transient روزانه محدود شده؛ بدون تغییر اسکیمای دیتابیس.
- `ZSM_VERSION` از 1.5.2 به 1.5.3.
- یکدست‌سازی هدر: `Domain Path: /languages` افزوده شد (در صورت نبود). بدون تغییر رفتار یا دیتابیس.

## 1.5.1 — به‌روزرسانی سازگاری (وردپرس 7.1 / PHP 8.5)
- سازگاری‌سازی با وردپرس 7.1.x و PHP 8.4/8.5: هدرهای «Requires at least: 6.6» و «Tested up to: 7.1» به‌روز شد؛ بدون تغییر در اسکیمای دیتابیس یا رفتار کاربر.
- مقادیر `send_method`/`encryption`/`backup_encryption` پیش از ذخیره با `wp_unslash` + `sanitize_key` پاک‌سازی می‌شوند.

## 1.5.0
بازطراحی برای هاست ایرانی + شرایط تحریم.

**حذف شد:**
- روش ارسال Mailgun API (شرکت Sinch/آمریکایی — قوانین Export Compliance روی حساب‌های مرتبط با ایران اعمال می‌شود).
- روش ارسال SendGrid API (شرکت Twilio/آمریکایی — همان محدودیت).
- تمام فیلدهای تنظیمات، بخش‌های فرم ادمین، و کد پشتیبان مربوط به این دو روش.

**نگه داشته شد (بدون تغییر منطقی):**
- روش SMTP (شامل SMTP خود هاست یا جیمیل).
- روش Brevo API (شرکت اروپایی، فقط HTTPS، محدودیت حساب مرتبط با ایران ندارد).
- زنجیره‌ی failover: روش اصلی ← SMTP پشتیبان (اختیاری) ← ارسال بومی هاست (اختیاری).
- صف retry با wp_cron و صفحه‌ی «گزارش ایمیل‌ها».
- رمزنگاری credential ها با Pas_Core_Crypto.

**اضافه شد:**
- Migration خودکار: اگر send_method قبلاً روی mailgun/sendgrid بود، به‌جای خالی‌ماندن بی‌صدا، به smtp برمی‌گردد.
- توضیح کوتاه در صفحه‌ی تنظیمات درباره‌ی این‌که چرا فقط دو روش باقی مانده و کدام‌یک برای هاست ایرانی مناسب‌تر است.
