# بازگشت (Rollback) — اکوسیستم پیوند امن v1

> **اصل طلایی:** بازگرداندن فایل‌ها به‌تنهایی، دیتابیس را برنمی‌گرداند.
> اگر در ارتقا Migration اجرا شده باشد، باید فایل **و** دیتابیس با هم بازگردانده شوند.

## ۰. سه سطح بازگشت

| سطح | چه زمانی | چه چیزی برمی‌گردد |
|---|---|---|
| A — بازگشت کد | فقط تغییرات فایل، بدون Migration | پوشه‌های افزونه |
| B — بازگشت کد + داده | Migration اجرا شده یا داده تغییر کرده | پوشه‌ها + دیتابیس |
| C — بازگشت کامل سایت | خرابی سرور یا فاجعه | دیتابیس + `wp-content` + کلید |

## ۱. سطح A — بازگشت کد

1. از پیشخوان، افزونه‌ها را **در ترتیب معکوس** غیرفعال کنید:
   `daily-feed → content-writer → payvand-contact → ui-kit → client-portal →
    quiz-enterprise → case-file → 2fa → smtp-mailer → sms-bridge → core`
2. پوشه‌های افزونه را با نسخهٔ قبلی جای‌گزین کنید:
   ```
   tar -xzf backup-plugins-<date>.tar.gz -C wp-content/
   ```
3. دوباره فعال کنید، این بار از core شروع کنید.
4. `wp plugin list` و صفحهٔ اصلی را بررسی کنید.

**هیچ‌گاه** برای بازگشت، افزونه را «حذف» نکنید؛ حذف کامل، `uninstall.php` را اجرا می‌کند
و ممکن است داده‌ها را پاک کند.

## ۲. سطح B — بازگشت داده

1. ابتدا کد را طبق سطح A برگردانید.
2. دیتابیس را بازیابی کنید:
   ```
   gunzip -c backup-db-<date>.sql.gz | mariadb -h<host> -u<user> -p <db>
   ```
3. گزینه‌های نسخهٔ Schema را بررسی کنید تا با کد هم‌خوان باشند:
   `pas_core_db_version`، `psy_quiz_db_version`، `pas_cf_db_version`، `zdp_db_version`.
4. بررسی کنید تعداد ردیف‌های جدول‌های اصلی با snapshot پیش از ارتقا برابر باشد.

> در آزمون این انتشار، بازگشت کد + فعال‌سازی مجدد، داده‌ها را دست‌نخورده نگه داشت:
> ۳۷ جدول، ۳ آزمون، ۳۸ مراجع، بدون تغییر.

## ۳. سطح C — بازگشت کامل

[DISASTER-RECOVERY.md](DISASTER-RECOVERY.md) را ببینید (بازیابی کامل سرور).

## ۴. چه چیزی نباید انجام شود

- اجرای `uninstall.php` در جریان بازگشت.
- حذف جدول‌ها با `DROP TABLE` یا خالی‌کردن با `TRUNCATE`.
- تولید یا تعویض کلید رمزنگاری برای «درست کردن» خطا.
- بازگشت فقط فایل‌ها وقتی Migration اجرا شده است.
