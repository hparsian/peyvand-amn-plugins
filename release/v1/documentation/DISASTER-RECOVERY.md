# بازیابی از فاجعه — اکوسیستم پیوند امن v1

این سند برای زمانی است که سرور از دست رفته یا سایت به‌کلی خراب شده است.
هدف: بازگرداندن **دیتابیس + فایل‌ها + کلید رمزنگاری** با ترتیب درست.

## ۰. چه چیزهایی باید در بکاپ باشد

| قلم | چرا حیاتی است | محل نگهداری |
|---|---|---|
| دیتابیس (۳۷ جدول) | مراجعان، پرونده‌ها، آزمون‌ها، لاگ‌ها | خارج از وب‌روت، رمزگذاری‌شده |
| `wp-content/plugins` | ۱۱ افزونه و نسخهٔ دقیق | همان بکاپ |
| `wp-content/uploads` | پیوست‌ها و فایل‌های بالینی | همان بکاپ |
| `wp-content/pas-encryption-key.php` یا مقدار `PAS_CORE_ENCRYPTION_KEY` | بدون آن داده‌های رمزی ناخوانا می‌شوند | **جداگانه**، رمزگذاری‌شده، دسترسی محدود |
| نسخهٔ PHP و WordPress | بازسازی دقیق محیط | در مانیفست وضعیت |
| فایل این انتشار (`checksums.sha256`) | تطبیق دقیق کد | مخزن Git |

> کلید رمزنگاری هرگز در همان آرشیوی نگه‌داری نشود که ZIPهای انتشار یا دیتابیس در آن است.

## ۱. ترتیب بازیابی (مهم)

1. **محیط**: PHP و WordPress با همان نسخه‌های ثبت‌شده بالا بیایید.
2. **کلید**: `pas-encryption-key.php` را در `wp-content/` قرار دهید (`chmod 600`) یا ثابت را در `wp-config.php` بگذارید.
3. **دیتابیس**: بکاپ را import کنید و `wp_pas_*`، `wp_psy_*`، `wp_zdp_*`، `wp_aco_*` را بررسی کنید.
4. **افزونه‌ها**: ZIPها را طبق ترتیب [DEPENDENCIES.md](DEPENDENCIES.md) نصب و فعال کنید.
5. **uploads**: بازگردانید.
6. **بررسی**: آزمون‌های بخش ۳.

```
# نمونه import
gunzip -c backup-db-2026-11-14.sql.gz | mariadb -h127.0.0.1 -u<user> -p <db>

# بررسی تعداد جدول
mariadb -h127.0.0.1 -u<user> -p -e "SELECT COUNT(*) FROM information_schema.tables WHERE table_schema='<db>';"
```

## ۲. بررسی رمزنگاری پس از بازیابی

با یک رکورد آزمایشی (نه دادهٔ واقعی مراجع):

1. یک رشتهٔ موقت را با `Pas_Core_Crypto::wrap_encrypted()` رمز کنید.
2. با `unwrap_decrypt()` بازگردانید و مقایسه کنید.
3. یک پاسخ آزمون موجود را رمزگشایی کنید و فقط **تعداد کلیدها** را بررسی کنید (محتوا را چاپ نکنید).

اگر رمزگشایی داده‌های موجود شکست خورد: کلید اشتباه است. بازیابی را متوقف کنید و کلید صحیح را
از بکاپ جداگانهٔ کلید بازگردانید؛ **هرگز** کلید جدید نسازید.
