# به‌روزرسانی — اکوسیستم پیوند امن v1

## ۱. ترتیب به‌روزرسانی

همیشه **core اول**، و سپس بقیه. اگرچه در آزمون‌ها نصب هم‌زمان نیز خطا نداد،
ترتیب زیر تضمین می‌کند قراردادهای `Pas_Core_*` پیش از مصرف‌کننده‌ها به‌روز شوند:

```
core → 2fa → sms-bridge → smtp-mailer → case-file → quiz-enterprise
     → client-portal → ui-kit → payvand-contact → content-writer → daily-feed
```

روش توصیه‌شده: **غیرفعال‌سازی گروهی، جای‌گذاری فایل‌ها، فعال‌سازی گروهی.**
روش جایگزین (بدون غیرفعال‌سازی) نیز در آزمون این انتشار آزمایش شد: جای‌گذاری
فایل‌های نسخهٔ جدید روی پوشهٔ نصب‌شده و سپس بارگذاری مجدد صفحهٔ پیشخوان.

---

## ۲. آنچه هنگام ارتقا حفظ می‌شود

- تمام جدول‌های داده و ردیف‌ها (در آزمون ارتقای این انتشار: ۳۷ جدول و ۸۳۹ ردیف بدون تغییر).
- گزینه‌های نسخهٔ Schema (`pas_core_db_version`، `psy_quiz_db_version`، `pas_cf_db_version`، `zdp_db_version`، `aco_db_version` و …).
- کلید رمزنگاری و داده‌های رمزشده (کلید را تعویض نکنید).

## ۳. تغییرات Schema

Migrationها idempotent هستند و نسخهٔ Schema را در همان گزینه‌ها ثبت می‌کنند.
هیچ `DROP TABLE` یا `TRUNCATE` در مسیر ارتقا اجرا نمی‌شود.
تنها استثناء، `uninstall.php` است که فقط با حذف کامل افزونه از پیشخوان اجرا می‌شود و
در فرآیند ارتقا/بازگشت هرگز اجرا نمی‌شود.

---

## ۴. مراحل عملی (Staging → Production)

1. از دیتابیس و `wp-content` بکاپ کامل بگیرید و **حجم و checksum** آن را ثبت کنید.
2. در محیط Staging همان نسخهٔ فعلی Production را بازیابی کنید.
3. ZIPهای جدید را طبق ترتیب بالا نصب کنید.
4. آزمون‌های پذیرش (بخش ۵) را اجرا کنید.
5. فقط در صورت سبز بودن همه، همین رویه را در Production تکرار کنید.
6. نسخهٔ هر افزونه و زمان ارتقا را ثبت کنید.

## ۵. آزمون پذیرش پس از ارتقا

| # | آزمون | معیار قبولی |
|---|---|---|
| 1 | `wp plugin list` | ۱۱ افزونه active با نسخهٔ مانیفست |
| 2 | باز شدن پیشخوان | بدون خطای PHP/Fatal |
| 3 | رمزگشایی یک پاسخ آزمون موجود | پر شدن آرایهٔ پاسخ‌ها (بدون تغییر داده) |
| 4 | قرارداد `psy_get_assessment_scores_for_phone` | حداقل یک ردیف برای مراجع دارای آزمون |
| 5 | رندر گزارش آزمون | HTML بدون `style="` درون‌خطی، دارای نمودار |
| 6 | پنل درمانگر | مشاهدهٔ فقط پرونده‌های تخصیص‌یافته |
| 7 | پنل مراجع | عدم نمایش دادهٔ مراجع دیگر |

## ۶. اگر ارتقا شکست خورد

به [ROLLBACK.md](ROLLBACK.md) مراجعه کنید. بازگرداندن فایل‌ها به‌تنهایی کافی نیست؛
اگر Migration اجرا شده باشد، دیتابیس هم باید بازیابی شود.
